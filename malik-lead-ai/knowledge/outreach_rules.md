# Outreach Rules — MalikAxiom Lead AI

> Internal knowledge base file for **MalikAxiom Lead AI**.
> Defines how future outreach must be constructed. Message generation itself is a future milestone.

---

## 1. Outreach Philosophy

Future outreach must be **personalized around an observed business opportunity**.

### Avoid (Generic)

> "Hi, we are a software company. Do you need a website?"

### Use (Evidence-Based Pattern)

**Observation → Relevant opportunity → MalikAxiom solution → Soft CTA**

1. **Observation** — state a factual, verified observation about the business.
2. **Relevant opportunity** — connect that observation to a real digital opportunity.
3. **MalikAxiom solution** — present the specific MalikAxiom service that addresses it.
4. **Soft CTA** — a low-pressure next step (e.g., a quick chat or short call).

## 2. Required Recommendations (Future System Output)

For each qualified lead, the system should eventually recommend:

- **Best outreach channel** (e.g., WhatsApp, email, LinkedIn, contact form)
- **Target person/role** where identifiable (e.g., owner, manager) — only if
  actually observed; otherwise mark as unknown
- **Outreach angle** — the specific observed opportunity being referenced
- **Personalized message** — following the pattern above
- **Why that angle is appropriate** — grounded in the lead's evidence

## 3. Message Rules

- Use the word **"challenges"** — never "problems" — when describing customer needs.
- **Never guarantee revenue or profit.**
- Reference only verified facts about the lead; never invent challenges,
  revenue, technology, customer volume, owner identity, or needs.
- Every message must be unique to the lead's observed situation.
- Keep the tone professional, concise, and respectful of the recipient's time.
- Do not fabricate urgency, familiarity, or prior contact.
- Only claim benefits MalikAxiom can actually deliver (see
  [business_digitalization.md](business_digitalization.md) for allowed claims).

## 4. Status

**Milestone 1 scope:** these rules are documented only.
Automated message generation, channel selection, and sending are **not implemented yet**.
